# Vitest — testy, dublery, tryb przeglądarki, testy mutacyjne

Wersje: napisane dla Vitest 5.0, działa od 3.0 (tabela niżej). Dowody tego, co uruchomiono: `skill.meta.json`.

## Pisanie testów
- **Tabele przykładów** z `it.each`; id przypadku i źródło trafiają do nazwy, granice poniżej/na/powyżej:
  ```ts
  // Źródło: H1-AC2 „5% od 10 sztuk” (konta firmowe)
  it.each([
    { id: 'TC-011', qty: 9,  expected: 900.00 },
    { id: 'TC-012', qty: 10, expected: 950.00 },
    { id: 'TC-013', qty: 11, expected: 1045.00 },
  ])('$id: $qty × 100.00 → $expected', ({ qty, expected }) => {
    expect(priceFor({ qty, unit: 100, business: true })).toBe(expected);
  });
  ```
  Oczekiwane wartości pochodzą ze specyfikacji (qa-spec-first-testing), nigdy z uruchomienia kodu.
- Pracuj w trybie watch (`npx vitest`); **nowy test musi najpierw paść**, z właściwego powodu.
- **Środowisko:** czysta logika domenowa w domyślnym środowisku `node`; zachowanie UI w **trybie przeglądarki** (prawdziwa przeglądarka)
  zamiast jsdom.
- **Znany defekt:** `it.fails('BUG-231: zaokrąglenie przy 100,00', …)` — test przechodzi, dopóki błąd istnieje, i robi się czerwony po poprawce;
  nie zmieniaj oczekiwania.
- **Testy właściwości** z fast-check dla niezmienników:
  ```ts
  import fc from 'fast-check';
  it('H2-AC1: części podziału zawsze sumują się do kwoty', () => {
    fc.assert(fc.property(fc.integer({ min: 0, max: 10_000_00 }), fc.integer({ min: 1, max: 12 }), (cents, n) => {
      const parts = split(cents, n);
      return parts.length === n && parts.reduce((a, b) => a + b, 0) === cents && Math.max(...parts) - Math.min(...parts) <= 1;
    }));
  });
  ```

## Dublery testowe na portach
- Podmieniaj tylko to, co przechodzi przez **port** (kursy walut, zegar, bramka płatności, repozytorium). Preferencja: **fake** (mała
  działająca wersja w pamięci) > **stub** (zaślepka ze stałymi odpowiedziami) > **mock** (weryfikacja wywołań). `vi.mock` własnego modułu to zapach —
  wiąże test z układem plików.
- **`vi.when`** (Vitest 5) — stub odpowiadający zależnie od argumentów; z `onUnmatched: 'throw'` każde wywołanie z niezdefiniowanymi argumentami
  pada głośno zamiast zwracać `undefined`:
  ```ts
  const getRate = vi.fn<(from: string, to: string) => number>();
  vi.when(getRate, { onUnmatched: 'throw' }).calledWith('EUR', 'PLN').thenReturn(4.30);
  ```
  Dokładne miejsce opcji sprawdź w dokumentacji API Vitest 5 dla swojej wersji. **Przed Vitest 5** nie ma `vi.when`:
  napisz stub ręcznie — `vi.fn((from, to) => { if (from === 'EUR' && to === 'PLN') return 4.30; throw new Error('unexpected ' + from + '/' + to); })`.
- **`clearMocks` jest domyślnie `true` w Vitest 5** — historia wywołań jest czyszczona przed każdym testem. Testy, które liczyły wywołania
  między testami albo polegały na historii z `beforeAll`, zmieniają zachowanie po aktualizacji. `restoreMocks`/`mockReset` nadal trzeba włączyć.

## Czas
```ts
beforeEach(() => { vi.useFakeTimers(); vi.setSystemTime(new Date('2026-03-02T10:00:00Z')); });
afterEach(() => { vi.useRealTimers(); });
```
Przesuwaj przez `vi.advanceTimersByTime(ms)` albo `await vi.runAllTimersAsync()`.

## Tryb przeglądarki i projects (testy komponentów)
```ts
// vitest.config.mts (albo "type": "module" w package.json — konfiguracja jest ESM)
import { defineConfig } from 'vitest/config';
import { playwright } from '@vitest/browser-playwright';
export default defineConfig({ test: { projects: [
  { test: { name: 'unit', environment: 'node', include: ['src/**/*.spec.ts'] } },
  { test: { name: 'browser', include: ['src/**/*.browser.spec.ts'],
            browser: { enabled: true, provider: playwright(), instances: [{ browser: 'chromium' }] } } },
] } });
```
W teście: `import { page } from 'vitest/browser'` i `await expect.element(page.getByRole('button', { name: 'Zapisz' })).toBeVisible()`.
Lokatory w Vitest 5 są ścisłe: lokator pasujący do kilku elementów pada. Testy komponentów pisane dawniej w
Playwright CT należą tutaj.

## Wybór, co uruchomić
- `vitest run --changed origin/main` — testy dotknięte diffem; `vitest related src/discount.ts --run` — testy importujące plik.
- `--project unit`, `--shard=1/3` (scalanie przez `--merge-reports`).
- W środowisku agenta (ustawiona zmienna `AI_AGENT`) Vitest 5 używa minimalnego reportera i nie włącza trybu watch; na starszych wersjach
  podawaj `--run` jawnie.

## Testy mutacyjne ze Strykerem (StrykerJS 10 + Vitest 5)
- Używaj **command runnera**: `testRunner: "command"`, `commandRunner: { command: "npx vitest run" }`. W sprawdzeniu fabryki dedykowany
  `@stryker-mutator/vitest-runner` dał z Vitest 5 **fałszywe 0%**, a command runner 93,55% i jednego przeżyłego mutanta, który wskazał
  rzeczywiście brakujący test.
- **Zawsze sprawdzaj wiarygodność wyniku.** 0% (wszystkie mutanty przeżyły) albo podejrzane 100% znaczy, że mutanty nie są aktywowane albo
  testy się nie uruchamiają — napraw konfigurację, zanim czytasz wyniki. Starsze konfiguracje runnerów Strykera/Vitest się nie przenoszą.
- Mutuj **tylko logikę domenową** (`mutate: ["src/domain/**/*.ts", "!src/**/*.spec.ts"]`).
- Command runner uruchamia całą komendę dla każdego mutanta, więc zawężaj:
  `npx stryker run --mutate "src/discount.ts:20-60"` dla zmienionych linii przed merge, `--incremental`, żeby użyć wcześniejszych wyników.
- Przebieg, który nie znajduje nic do testowania, kończy się błędem; `--allowEmpty` akceptuje to świadomie (np. PR bez zmian w domenie).
- Do triażu przez agenta używaj raportu **json** (`reporters: ["json", "clear-text", "progress"]` → `reports/mutation/mutation.json`);
  nie ma wbudowanego reportera markdown. Co zrobić z przeżyłymi: qa-spec-first-testing.

```json
{
  "testRunner": "command",
  "commandRunner": { "command": "npx vitest run --project unit" },
  "mutate": ["src/domain/**/*.ts", "!src/**/*.spec.ts"],
  "reporters": ["json", "clear-text", "progress"],
  "incremental": true
}
```

## Zależne od wersji
| Wersja | Co się zmieniło |
|---|---|
| 3.0 | minimalna wspierana podstawa |
| 3.2 | `projects` w konfiguracji (zastępuje plik workspace) |
| 4.0 | tryb przeglądarki stabilny; providery jako pakiety (`@vitest/browser-playwright`); usunięty workspace; usunięte `coverage.all`; spłaszczone `poolOptions`; usunięty reporter `basic` |
| 5.0 | Node ≥ 22.12, Vite ≥ 6.4; `clearMocks: true` domyślnie; `vi.when`; ścisłe lokatory przeglądarki; wyjście reporterów w `.vitest/` |

## Przykład
„Stryker na Vitest 5 pokazuje 0% dla `src/discount.ts`”:
1. Przełącz na `testRunner: "command"` z `npx vitest run`.
2. Uruchom `npx stryker run --mutate "src/discount.ts"`; oczekuj wiarygodnego wyniku, nie 0%.
3. Nadal 0% → uruchom samo `npx vitest run`: czy testy przechodzą i importują `src/discount.ts` (nie zbudowaną kopię w `dist/`)?
4. Przeżyłe mutanty czytaj z `reports/mutation/mutation.json`, triaż według qa-spec-first-testing.
