# Next.js (App Router)

**First check the version** (`detect_stack.py` / `package.json`) and whether the project has `cacheComponents: true`
in `next.config`. The React rules (purity, state, effects) are in fw-react; here only what Next.js adds.

**Version-matched documentation takes precedence over the model's memory.** Since 16.3 the `next` package contains
documentation (`node_modules/next/dist/docs/`), and `next dev` writes `AGENTS.md` / `CLAUDE.md` into the project with
a pointer to it. In the factory:
- the `guard_paths` hook blocks reading `node_modules/`, so you do not read that copy. Documentation outside `node_modules`
  (`.next-docs/`) is provided by `npx @next/codemod@canary agents-md`; the human runs it, because the command changes the agent
  instruction files;
- the project's `CLAUDE.md` file belongs to the factory. When `next dev` has changed it, show the diff to the human and do not
  merge it yourself [unverified: the way `next dev` writes it was not checked];
- when `.next-docs/` is in the project, you check APIs in it before use.

## Rules
1. **Server Components by default.** You put `'use client'` as low in the tree as possible (a leaf with interaction).
   - Props from the server to the client must be serializable: data, JSX, promises, Server Functions — not classes or plain functions.
   - Mark server-only code (keys, database access) with `import 'server-only'`.
2. **You fetch data on the server**, in a component or in a data access layer (DAL):
   - the DAL checks permissions and returns minimal DTOs, not database records;
   - you wrap slow parts in `<Suspense>` or `loading.tsx` so that the page streams;
   - you run independent queries in parallel (`Promise.all`), without an `await` cascade.
3. **A Server Action is a public POST endpoint.** Anyone can call it directly, bypassing the page and the layout.
   - **In every action** you check the session, the permission to the specific resource (the owner — otherwise IDOR) and validate
     the input (e.g. Zod). A check in `layout.tsx` or on the page does not protect the action.
   - Actions are for mutations, not for reading data.
   - You return a business rejection as state for `useActionState`; an exception only for unexpected errors.
   - After a mutation you refresh the data:
     - `updateTag(tag)` — immediately, with read-your-own-writes (16+, only in an action);
     - `revalidateTag(tag, 'max')` — in the background, stale-while-revalidate;
     - `revalidatePath(path)`;
     - `refresh()` — uncached data and the client router (16+);
     - then possibly `redirect()`.
4. **Calls that require the request are asynchronous** (15+, in 16 with no synchronous version): `await params`,
   `await searchParams`, `await cookies()`, `await headers()`, `await draftMode()`. Page types are generated by `next typegen`
   (`PageProps<'/products/[id]'>`).
5. **Cache:**
   - since 15 `fetch`, GET Route Handlers and client navigations are **not** cached by default;
   - with **Cache Components** (16, `cacheComponents: true`) you enable the cache explicitly with the **`'use cache'`** directive (a file,
     a component or a function) with `cacheLife('hours')` and **`cacheTag('products')`**; you read request-dependent data outside
     the cached function or in `<Suspense>` (`'use cache: private'` for user data);
   - partial prerendering is then the default: a static shell plus streamed dynamic parts;
   - without Cache Components the old model applies (`fetch` with `next: { revalidate, tags }`, `export const revalidate`).
6. **`proxy.ts` (16)** replaces `middleware.ts`; it runs on Node.js. You use it for redirects and headers, not as
   the only authorization: the CVE-2025-29927 vulnerability allowed bypassing it. You also check permissions in the DAL and in actions.
7. **Environment variables:** only `NEXT_PUBLIC_*` reach the browser and they are inlined at `next build`
   (a change requires a rebuild). You do not prefix secrets.
8. **Route files:**
   - `page`, `layout`, `loading`, `error` (a client component with `reset`), `not-found`;
   - `route.ts` cannot sit next to `page` in the same segment;
   - parallel routes (`@slot`) require `default.tsx` (16);
   - metadata through `generateMetadata`, static paths through `generateStaticParams`;
   - a Route Handler serves webhooks, a public API and integrations; you do mutations from your own UI with Server Actions;
   - `redirect()`, `notFound()`, `forbidden()` throw a special exception: do not call them in a `try` whose `catch`
     swallows errors;
   - `useSearchParams()` in a static route requires `<Suspense>` above the component, otherwise the whole route renders
     in the browser.
9. **Tests:**
   - domain logic and synchronous components — Vitest or Jest with Testing Library (tool-vitest, tool-jest);
   - **asynchronous Server Components** — e2e tests (tool-playwright), because Vitest does not render them;
   - you test Server Actions as functions: no session, someone else's resource and bad input give a rejection.
10. **Updates and security:**
    - you update with codemods: `npx @next/codemod@canary upgrade latest` (since 16.1 also `next upgrade`);
    - in 2025–2026 there were several critical patches, including an RCE in the RSC protocol (CVE-2025-66478 / React CVE-2025-55182);
    - the project should have the latest patch of its line (16.3.x; 15.5.x is the maintenance line);
    - you report an older version to the human and do not upgrade it yourself (core-stack-sync).

## Domain concepts in Next.js — where things live
| Concept (glossary) | Place in a Next.js application |
|---|---|
| **value object** | pure TS in `domain/` (lang-typescript), used on both sides; it crosses the server→client boundary as plain data and is rebuilt by a factory |
| **entity** | a domain type in `domain/`; a Server Component gets it from the DAL and passes it on as a DTO |
| **variants** | a discriminated union; a `switch` on `kind` in the component or separate variant components |
| **operation result** | the value returned by a Server Action (`{ ok: true } \| { ok: false, reason }`) and read through `useActionState` |
| **aggregate** | on the server: a module in `domain/` loaded and saved by a repository in an action or a Route Handler, in one transaction; never in a client component |
| **state machine** | the aggregate's methods on the server side; in the UI `useReducer` only for interaction state |
| **event** | a domain event from the aggregate published after the save (outbox — be-messaging-outbox); in the UI cache invalidation through `updateTag`/`revalidateTag` |
| **policy** | a pure function in `domain/`, called in an action; configuration from server environment variables |
| **specification / rules** | pure functions in `domain/`: the same ones in form validation on the client and in the action on the server (the server decides) |
| **repository / port** | an interface in `domain/`, the implementation in `lib/db` with `import 'server-only'`; the DAL above it checks permissions |
| **read model** | a read function in the DAL, cached with `'use cache'` + `cacheTag`; pages only read |
| **module** | a feature directory (`features/<name>/` with `domain/`, `server/`, `ui/`) and a route group `app/(name)/`; `domain/` without imports from `next/*` and `react` |

## Version-dependent
| Version | Changes relevant to this skill |
|---|---|
| 14 | App Router stable, Server Actions stable (14.0); `fetch` cached by default; synchronous `params`/`cookies()` |
| 15 | React 19; **asynchronous** `params`, `searchParams`, `cookies()`, `headers()`, `draftMode()` (with a warning on synchronous access); `fetch`, GET Route Handlers and client navigations not cached by default; `next/form`; `instrumentation.js` stable; 15.5: middleware on Node.js stable, `typedRoutes`, `next typegen`, `next lint` being deprecated. The 15.5.x line is in maintenance |
| 16.0 | **Turbopack the default** (dev and build; `--webpack` as the way out); **`proxy.ts` instead of `middleware.ts`** (Node.js); **Cache Components** (`cacheComponents`, `'use cache'`, stable `cacheLife`/`cacheTag`); `revalidateTag(tag, profile)` requires a second argument; new `updateTag()` and `refresh()`; **synchronous access removed** for `params`/`cookies()` etc.; removed `next lint`, `experimental.ppr`, AMP, `serverRuntimeConfig`/`publicRuntimeConfig`; `default.tsx` required for slots; `reactCompiler` stable (disabled by default); Node ≥20.9, TS ≥5.1 |
| 16.1 | Turbopack's on-disk cache in `next dev` by default; `next upgrade` |
| 16.2 | deployment adapters stable; faster dev start |
| 16.3 | on-disk cache also for `next build`; type checking with TypeScript 7; `catchError` from `next/error`; `next/root-params`; instant navigations (`partialPrefetching` with Cache Components) |

Migration 15 → 16: `npx @next/codemod@canary upgrade latest`, and if needed separately
`npx @next/codemod@canary next-async-request-api .`, `middleware-to-proxy` and `next-lint-to-eslint-cli .`. Then
`next build`, tests and a review of `revalidateTag` (the second argument). Equivalents for 14/15 are in `references/patterns.md`.

## Checklist
- [ ] the Next.js version and `cacheComponents` checked; the APIs used are available in that version
- [ ] every Server Action checks the session, the resource owner and the input; a test for missing permissions
- [ ] server code with `server-only`; no secrets in `NEXT_PUBLIC_*`
- [ ] `'use client'` only in leaves with interaction; data fetched on the server
- [ ] an explicit refresh after a mutation (`updateTag` / `revalidatePath` / `refresh`)
- [ ] a version with the latest security patch of its line, or a report for the human
