# Running sessions

## Outline (45–60 min)
1. Welcome, the purpose ("we are testing the product, not you"), a reminder of the consent, start the recording after confirmation (5 min).
2. Warm-up: context, the last time the participant did what we are studying (10 min).
3. Tasks or the main topic (25–30 min).
4. Summary questions, SEQ/SUS in a test (5 min).
5. Thanks, the incentive, a reminder of the rights and the retention period.

## Questions
- Instead of "Do you like filters?" → "Tell me about the last time you looked for an invoice from half a year ago."
- Ask about past behaviour, not future declarations ("would you buy" inflates interest).
- Follow up: "What did you do then?", "What did you expect?", "Why?" — one question at a time.
- Silence after an answer for 3–5 seconds; people often add what matters.

## Moderator mistakes
| Mistake | Effect | Fix |
|---|---|---|
| leading questions ("Isn't this convenient?") | nodding along | an open question |
| explaining the interface | a distorted result | "What would you do next?" |
| judging the answer ("good!") | the participant seeks approval | a neutral "thank you" |
| words from the interface in the task | the task is too easy | a goal scenario without button names |
| no pilot | a broken task in session 1 | a pilot |
| conclusions during the session | bias | note facts, interpret in the synthesis |

Observers from the team: a separate channel, no interruptions; they note in an observation table (time, quote, event).
Unmoderated test: unambiguous tasks, a mandatory pilot, quality control of answers (reject "blind clicking").
